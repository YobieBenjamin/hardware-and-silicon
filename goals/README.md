# Goals of the Safety Governor program

The documents that define what this program is for and how its work is judged. Read GOAL.md first.

| File | What it is |
|---|---|
| GOAL.md | The north star: a chip that stops bad actions from AI, because AI cannot govern AI; mandatable on every AI server; working in one server, a rack and a fleet of up to hundreds of thousands of racks. Every piece of work is judged against it. |
| ASPIRATION.md | The destination in detail (23 October 2026): the governor on a module inside a real NVIDIA-powered server, the authority it must earn, and the acceptance conditions the software proof must establish before any hardware. The original with its figures is in the safety-governor repo, docs/vision/. |
| ADVERSARIAL-FUNCTION-AUDIT-PROMPT.md | The adversarial feature and function audit: every requirement tested at server, rack, fleet and mandate scale, by fresh independent teams, producing a problem catalog with a failing test for each problem. |
| PROBLEM-TO-SILICON-PIPELINE.md | How every problem gets fixed: catalog, register, reproduce, fix in code, prove, verify with a fresh auditor, plan for silicon. |

Copies of these files are kept in the claude.ai project "Hardware and Silicon" (folder design/) and in the program's
memory. Last updated 25 October 2026.
